# زمین چمن ایرانیان

اپ اندروید مدیریت زمین چمن (رزرو تایم، حسابداری، مشتریان، گزارش‌گیری) با رابط کاملاً فارسی و راست‌به‌چپ.
تمام داده‌ها **فقط روی همین گوشی** (آفلاین، بدون اینترنت و بدون سرور) ذخیره می‌شود.

> ⚠️ **وضعیت کد:** این پروژه در محیط ساخت من (بدون Android SDK و Gradle و اینترنت) نوشته شد و
> **کامپایل یا روی گوشی اجرا نشده است.** منطق تقویم شمسی جداگانه با محاسبه‌ی عددی راستی‌آزمایی شد،
> اما ممکن است در اولین Build چند خطای کوچک کامپایلی (import، نوع داده، هشدار API) ظاهر شود.
> این‌ها معمولاً در چند دقیقه در Android Studio برطرف می‌شوند. بعد از اولین Build موفق، حتماً
> `./gradlew test` و یک تست کامل روی گوشی انجام دهید.

## ساخت و اجرا
1. **Android Studio** (نسخه‌ی Koala یا جدیدتر) را نصب کنید.
2. پوشه‌ی `ZaminChaman` را با `File > Open` باز کنید و صبر کنید Gradle Sync تمام شود (اولین بار به اینترنت نیاز دارد).
   - اگر Android Studio پیشنهاد به‌روزرسانی AGP/Kotlin داد، بپذیرید یا نسخه‌های `build.gradle.kts` را با هم هماهنگ کنید.
3. روی گوشی یا شبیه‌ساز (Android 8.0 / API 26 به بالا) Run کنید.
4. خروجی نصبی: `Build > Build Bundle(s) / APK(s) > Build APK(s)`.

اطلاعات ورود اولیه در مستند کارفرما آمده است؛ **روی صفحه‌ی ورود هیچ‌جا نمایش داده نمی‌شود** و از «تنظیمات» قابل تغییر است
(رمز فقط به‌صورت هش PBKDF2 ذخیره می‌شود).

## به‌روزرسانی بدون از دست رفتن اطلاعات
- `applicationId` (`com.zaminchaman.app`) را **هرگز** تغییر ندهید.
- همیشه با **همان keystore** امضا کنید و آن را در چند جای امن نگه دارید؛ با keystore دیگر، گوشی اجازه‌ی آپدیت روی نسخه‌ی قبلی را نمی‌دهد.
- `versionCode` را در هر انتشار زیاد کنید.
- هر تغییر در ساختار دیتابیس باید با Migration باشد (راهنما در `docs/ARCHITECTURE.md`). `fallbackToDestructiveMigration` عمداً استفاده نشده است.

## فونت وزیرمتن (اختیاری)
فونت پیش‌فرض سیستم فارسی را کامل پشتیبانی می‌کند. برای وزیرمتن: فایل‌های ttf را در `app/src/main/res/font/` بگذارید و
در `ui/theme/Theme.kt` مقدار `AppFontFamily` را مطابق کامنت همان فایل تغییر دهید.

## ساختار
جزئیات معماری، جدول‌ها، فرمت Backup و روش Migration در `docs/ARCHITECTURE.md`.

## ساخت APK با GitHub Actions
فایل `.github/workflows/build.yml` با هر push روی شاخه‌ی `main` (یا دکمه‌ی Run workflow) تست‌ها را اجرا و APK را می‌سازد.
خروجی: صفحه‌ی Actions ← آخرین اجرا ← بخش Artifacts ← `zamin-chaman-apk`.

برای نسخه‌ی نهایی (قابل آپدیت بدون از دست رفتن اطلاعات) باید با keystore ثابت امضا شود:
1. یک بار روی کامپیوتر: `keytool -genkeypair -v -keystore release.jks -alias zamin -keyalg RSA -keysize 2048 -validity 10000`
2. در GitHub: Settings ← Secrets and variables ← Actions، این ۴ Secret را بسازید:
   `KEYSTORE_B64` (خروجی `base64 -w0 release.jks`)، `KEYSTORE_PASSWORD`، `KEY_ALIAS` (مثلاً zamin)، `KEY_PASSWORD`.
3. فایل `release.jks` و رمزها را در چند جای امن نگه دارید و هرگز در مخزن commit نکنید.
بدون این Secretها فقط APK آزمایشی (debug) ساخته می‌شود؛ هر بار با کلید متفاوت امضا می‌شود، پس برای استفاده‌ی واقعی مناسب نیست.
